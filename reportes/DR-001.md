# DR-001 — Reporte de Defecto (simulado)

## Título
El badge del carrito no incrementa a "2" tras agregar un solo producto (defecto simulado)

## Severidad
Media

## Prioridad
Media

## Ambiente
- **Sitio bajo prueba:** https://www.saucedemo.com
- **Navegador:** Chromium (Desktop Chrome), vía Playwright
- **Usuario de prueba:** `standard_user`
- **Test automatizado:** `tests/clase07.spec.ts` → `Comparar estados antes y después de una acción`

## Descripción
Este defecto fue **simulado a propósito** siguiendo el Paso 3 del Laboratorio 07, para
practicar el ciclo completo de detección y documentación de un fallo con evidencia de
Playwright. No es un defecto real del sitio SauceDemo.

Se modificó temporalmente la aserción del test para esperar que el badge del carrito de
compras mostrara `"2"` después de agregar **un solo** producto al carrito, en lugar del
valor correcto `"1"`.

## Pasos para reproducir
1. Navegar a `https://www.saucedemo.com`.
2. Iniciar sesión con el usuario `standard_user` / `secret_sauce`.
3. En la página de inventario, agregar el primer producto al carrito (botón "Add to
   cart" del primer ítem).
4. Verificar el texto del badge del carrito (`.shopping_cart_badge`).

## Resultado esperado
`"2"` (valor forzado a propósito en la aserción del test, para simular el defecto)

## Resultado obtenido
`"1"` (el valor real y correcto que muestra el sitio: un producto agregado = badge en 1)

## Evidencia
- **Error de Playwright:**
  ```
  Error: expect(locator).toHaveText(expected) failed
  Locator:  locator('.shopping_cart_badge')
  Expected: "2"
  Received: "1"
  Call log:
    - locator resolved to <span class="shopping_cart_badge" data-test="shopping-cart-badge">1</span>
  ```
- **Screenshot del fallo:** [`evidencias/clase07/DR-001-fallo-badge.png`](../evidencias/clase07/DR-001-fallo-badge.png)
  (capturado automáticamente por Playwright gracias a `screenshot: 'on'` en `playwright.config.ts`)
- **Video:** generado automáticamente por Playwright (`video: 'on'`) en

- **Trace:** generado automáticamente por Playwright (`trace: 'on'`) en

  ```
  npx playwright show-trace test-results/clase07-.../trace.zip
  ```
  o desde el reporte HTML (`npx playwright show-report`) haciendo clic en el enlace

## Análisis (Error → Defecto → Fallo)
Aplicando la cadena causal vista en clase:
- **Error:** al escribir la aserción del test, se asumió (a propósito, para esta
  simulación) que agregar un producto dejaría el badge en `"2"`.
- **Defecto:** la línea `await expect(badgeDespues).toHaveText('2');` quedó en el código
  del test con un valor incorrecto — el defecto vive en el test, no en el sitio.
- **Fallo:** al ejecutar el test, la aserción falla porque el sitio real muestra `"1"`,
  que es el comportamiento correcto.

Esto también ilustra el caso de un **fallo sin defecto real en el sistema**: el fallo se
originó por un error en la propia prueba automatizada, no por un bug del producto.

## Estado
Cerrado — defecto simulado y revertido. El valor de la aserción se restauró a
`toHaveText('1')` y el test vuelve a pasar correctamente.
